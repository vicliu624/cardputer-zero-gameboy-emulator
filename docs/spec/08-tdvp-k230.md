# 08. TDVP K230 Device Profile And opkg Delivery

## Classification

This is a structural product extension: the frontend now has a second device
presentation and delivery target. It does **not** change the emulator core,
ROM ownership, or the project's user-data boundary. The K230 now has a
dedicated large-screen application layout; its UI contract is owned by
`10-tdvp-k230-large-screen-ui.md`.

The K230 profile is named:

```text
tdvp-k230
```

The feed platform it supports is:

```text
tdvp-k230-r1
tdvp-k230-br2025.02.1-glibc2.33-rv64-lp64d-k6.6.36-r1
```

## Confirmed Compatibility Boundary

| Property | Required value |
| --- | --- |
| SoC | Kendryte K230 |
| OS baseline | Buildroot 2025.02.1 |
| CPU ABI | RISC-V 64-bit LP64D |
| C library | glibc 2.33 |
| Kernel baseline | Linux 6.6.36 |
| User-visible output | 1232x568 landscape |
| Native KMS scanout | 568x1232 portrait buffer on the verified RM69A10 DSI connector |
| System graphics boundary | Application-local Linux DRM/KMS scanout through `/dev/dri/card0` |

The platform ABI marker is owned by the base firmware and the feed injects it
into the application package. Application code and packages must not replace
the loader, glibc, kernel, KPU/GPU stack, DRM driver, or base display
configuration. The application may temporarily program the selected KMS CRTC
and must restore its captured CRTC state when it exits.

## Rendering Contract

This document owns the K230's physical DRM/KMS contract. The application
layout is profile-specific: Cardputer Zero remains `320x170`, while TDVP K230
uses the `410x189` large-screen canvas specified in
`10-tdvp-k230-large-screen-ui.md`. Both profiles preserve the native
`240x160` GBA source frame.

`tdvp-k230` enumerates application-accessible `/dev/dri/cardN` DRM primary
nodes and selects the connected KMS connector that advertises either the
logical landscape `1232x568` mode or the K230 panel's native `568x1232`
scanout mode. It creates an XRGB8888 dumb scanout buffer, programs the
selected CRTC, and renders the internal canvas to this integer destination in
the user-visible landscape coordinate system:

```text
source:        410x189
integer scale: 3
destination:   1230x567
origin:        x=1, y=0
output:        1232x568
```

The one-pixel edge margin is intentional. When the selected scanout is the
native `568x1232` K230 mode, the application maps this landscape rectangle
counter-clockwise into the raw DRM buffer, matching the firmware's verified
`fbcon=rotate:3` panel orientation. This is a coordinate conversion at the
application/DRM boundary; it does not write fbdev or alter the system display
configuration. Non-uniform scaling, bilinear filtering, and direct fbdev
writes remain forbidden. The generic SDL path is only a development fallback
when native DRM/KMS cannot be opened; it is not the target-device graphics
contract.

## Input Contract

The normal keyboard contract remains valid: arrows or W/A/S/D for the D-pad;
J/K for A/B; U/I for L/R; Enter for Start; Space for Select; and 4–8 for app
actions.

The TDVP keyboard's visible function row additionally maps as follows:

| Key | Action |
| --- | --- |
| F1 | MENU |
| F2 | SAVE |
| F3 | LOAD |
| F4 | FAST |
| F5 | CHEATS |

No device-specific input event may bypass `InputMapper` or write directly to
the emulator core.

## Package Boundary

The TDVP package is `tdvp-cardputer-zero-gba`. It is built by the reviewed
recipe in the sibling `embedded-opkg-feed` repository against the selected
platform SDK. Its payload contains only application-owned paths:

```text
/opt/tdvp-cardputer-zero-gba/cardputer-zero-gba
/usr/bin/cardputer-zero-gba
/usr/share/applications/tdvp-cardputer-zero-gba.desktop
/usr/share/icons/hicolor/128x128/apps/cardputer-zero-gba.png
/usr/share/doc/tdvp-cardputer-zero-gba/
```

The `/usr/bin` wrapper selects the `tdvp-k230` profile and deliberately does
not force an SDL video driver. It never creates a system service or sets a
global display backend. Package build output, `.ipk` files, indexes, and
signatures are release artifacts and do not belong in source control.

## K230 Build Rule

The package must be built from the bundled SDL2 and mGBA source revisions with
the exact K230 Buildroot SDK/toolchain file. The build intentionally prefers
the bundled static SDL2 target so it does not assume an SDK-specific `SDL2Config`
package, and disables SDL's Wayland/KMSDRM video backends because the native
adapter uses the kernel DRM/KMS UAPI directly. Audio, C++ runtime, and glibc
remain base-firmware dependencies guarded by the platform ABI marker.

Do not publish a package built with a host RISC-V compiler, a generic Debian
RISC-V sysroot, a different Buildroot release, or a different glibc ABI.
